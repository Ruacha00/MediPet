# 02: 支持一轮省略式选科追问

**What to build:** 让就诊参与者先陈述症状、下一轮再用“那挂哪科”等省略表达追问时得到确定性人工导诊，同时避免更旧症状、Assistant 回复或历史方位选择污染当前判断。

**Blocked by:** 01: 结构化当前轮症状选科边界.

**Status:** resolved

- [x] 在紧急转介未命中后加载一次有界的已完成消息历史；紧急转介和幂等重放不得新增历史读取。
- [x] 通过当前轮标识排除已经持久化的当前参与者消息，再从同一就诊事项中选择最近的一条更早参与者消息，并跳过中间的 Assistant 消息。
- [x] 只把这一条更早参与者消息提供给策略，不向更早历史继续搜索症状。
- [x] 上一条参与者消息只在当前消息属于省略式选科、比较、适合性或目的地追问时提供症状上下文；普通目录查询和其他当前请求不得继承上一轮症状。
- [x] “孩子发烧了”后追问“那要挂哪科”产生 `FOLLOWUP_SYMPTOM_ROUTING_REQUEST` 原因，并在第二轮以零新增模型和 Tool 调用返回人工导诊。
- [x] 上一轮陈述症状后询问“儿科有哪些医生”固定为明确目标放行；询问“儿科是否合适”固定为人工导诊。
- [x] 测试证明当前消息不会被误当作上一条消息，Assistant 消息会被跳过，且两轮以前的症状不会影响新的目录、号源或方位请求。
- [x] 从历史恢复的院内方位选择不作为策略放行信号；既有方位解析只在策略允许进入 Agent 后执行。
- [x] 历史读取失败、流取消、运行失败、幂等重放、审计和指标继续使用既有终态语义。
- [x] 聚焦多轮测试、现有 Assistant 回归、Ruff 和 Pyright 通过，并在提交前完成非 partial、非 truncated 的 GitNexus change analysis。

## Answer

Assistant 现在只读取一次有界已完成历史，通过 turn 标识排除当前消息并跳过 Assistant 消息，只把最近一条更早参与者消息用于省略式选科追问；Agent 的原上下文窗口与方位解析边界保持不变。
