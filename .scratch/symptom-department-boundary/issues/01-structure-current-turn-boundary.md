# 01: 结构化当前轮症状选科边界

**What to build:** 让就诊参与者在当前轮提出症状选科请求时稳定得到人工导诊提示，同时让其已经明确选择的科室、院内服务地点或号源继续进入现有就诊协助，并以类型化结果解释每次阻断或放行。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 在修改现有策略入口前完成精确的上游影响分析；若结果仍为 HIGH，保留并核对 Assistant、HTTP turn 流程和直接测试依赖。
- [x] 策略输入固定为当前消息、可选的上一条参与者消息和当前轮是否选择号源；本票只使用当前消息与当前轮号源选择，上一条参与者消息保持为空。
- [x] 策略结果固定为人工导诊、明确目标放行和普通 Agent 放行三种类型，并使用 spec 规定的五个原因码；Agent 是否可执行由结果类型派生。
- [x] 当前症状加选科、比较、目的地或适合性判断请求产生固定人工导诊回复；“发烧，儿科合适吗”不得因为包含科室名称而放行。
- [x] 当前消息明确表示已经决定科室并请求查询，或当前轮提交了明确号源选择时，产生明确目标放行；目标真实性仍交给受信任 Tool 验证。
- [x] 症状陈述整理、一般门诊流程和其他不要求根据症状判断科室的请求产生普通 Agent 放行。
- [x] Assistant 在参与者消息持久化和助手消息幂等认领之后，先执行紧急转介，再调度结构化策略；明显急症与选科同时出现时仍返回紧急转介。
- [x] 人工导诊路径保持完成终态以及文本后完成的事件顺序，并证明模型请求和 Tool 调用均为零；两个允许结果汇入现有 Agent 路径。
- [x] 切换唯一生产调用者后移除旧的字符串或空值策略入口，不修改客户端协议、Agent 请求契约、能力快照、Tool 授权或持久化接口。
- [x] 以 `MediPetAssistant.handle_turn` 为主验收缝覆盖阻断、放行、紧急优先级、持久化和事件行为；纯策略表驱动测试只补充结果、原因码和字段不变量。
- [x] 聚焦测试、Ruff 和 Pyright 通过，并在提交前完成非 partial、非 truncated 的 GitNexus change analysis。
