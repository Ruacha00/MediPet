# 就诊事项历史记录管理

Type: spec
Status: resolved

## Problem Statement

MediPet 已能创建、列出和切换就诊事项，但历史列表不能改名、归档或恢复事项。当前 Web 还把空列表替换成固定 demo 事项，并在页面启动时先加载固定 demo 历史；因此参与者无法可靠整理历史记录，也无法让“没有活动事项”成为真实状态。

本切片提供轻量的历史记录管理，不建设永久删除或数据保留体系。归档是可逆的事项生命周期变化，不删除消息、操作提案、收据、审计或其他业务记录。

## Solution

- 保留 `VisitMatter` 作为内部领域单位，界面将列表区域称为“历史记录”。
- 每个事项继续使用现有 `title`；创建时若未提供标题，后端按服务医院本地时间生成确定性默认标题，例如“9 月 1 日 14:32 就诊事项”。默认标题不调用模型，也不截取参与者消息。
- 参与者可以改名活动或已归档事项，标题仍受现有长度和空白校验约束。
- 为事项增加可空的 `archived_at`。`null` 表示活动，非空表示已归档；`visit_stage` 继续只描述诊前或诊中阶段，不承载归档状态。
- 默认列表只返回活动事项，并提供显式的已归档列表。归档和恢复均幂等。
- 已归档事项仍可查看历史和改名，但不能发送新消息或确认操作；恢复后才能继续使用。
- 只有不存在 pending/streaming assistant message、运行中 turn 或 pending action proposal 时才能归档。冲突返回稳定的 typed error 和 HTTP 409，不自动确认、拒绝或取消医院操作。
- 改名、归档和恢复不改变用于“最近消息活动”排序的时间。恢复后的事项回到其原有消息活动位置。
- 归档当前事项后，Web 选择剩余活动事项中最近有消息活动的一项；若没有活动事项，则显示真实空状态和“新建就诊事项”入口，不创建或回退到 demo 事项。
- 页面初始加载必须先确定活动事项 ID，再读取同一事项的历史，不能把固定 demo 历史赋给另一个事项。

## Interface Decisions

- `VisitConversationStore` 增加参与者范围内的 rename、archive、restore 和按 lifecycle 列表能力；In-memory 与 PostgreSQL 实现必须通过同一契约测试。
- `VisitMatterSummary` 和 HTTP/TypeScript 响应增加归档时间或等价的明确 lifecycle 表示。
- HTTP 提供显式的 rename、archive 和 restore 操作，并区分活动列表与已归档列表；调用方不能通过任意字段 PATCH 修改患者、参与者或就诊阶段。
- 聊天和操作确认入口必须拒绝已归档事项，历史读取保持可用。
- 归档不是永久删除，不级联清理任何记录，也不改变已经发生的预约等医院动作。

## Acceptance Criteria

- [x] Alembic 迁移可重复地增加归档生命周期字段，现有事项迁移后保持活动状态。
- [x] 未显式命名的新事项得到基于服务医院本地时间的确定性默认标题。
- [x] 活动和已归档事项均可改名，且不会触发模型调用或复制参与者消息作为标题。
- [x] 活动列表默认排除已归档事项，已归档列表可单独加载并恢复事项。
- [x] 归档和恢复保持幂等、参与者范围隔离，并且不改变消息活动排序。
- [x] 正在生成回答或存在待确认操作时，归档返回冲突且不改变任何业务状态。
- [x] 已归档事项可读取历史，但聊天和操作确认返回明确的 archived 错误；恢复后重新可用。
- [x] 归档当前或最后一个活动事项后，Web 正确切换或显示真实空状态，不回退到 demo 事项。
- [x] 桌面和移动端均支持改名、查看已归档事项、归档和恢复，并呈现忙碌与错误状态。
- [x] Store 契约、迁移、HTTP、组件和浏览器测试覆盖上述行为。

## Risk Gate

GitNexus 对 `visit_context` 的上游影响分析为 **HIGH**：该路径同时服务聊天 turn 与操作确认。实施前必须重新运行 impact analysis，向实施者展示 HIGH 风险，并重点验证 Assistant、HTTP、In-memory/PostgreSQL Store、操作确认和历史恢复。不得把 Protocol 动态分派产生的 `UNKNOWN` 调用结果视为未使用。

## Out of Scope

- 永久删除就诊事项、消息、收据或审计。
- 数据保留、匿名化、导出和合规删除策略。
- 自动生成或模型总结标题。
- 归档时自动取消预约、确认或拒绝待处理操作。
- 为满足目标目录而预先拆分 Assistant、Runtime、Delivery 或持久化模块。
