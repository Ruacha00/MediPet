# 独立就诊事项对话管理

Type: spec
Status: resolved

## 目标

把“新建对话只是清空当前界面”的行为改为持久化的独立就诊事项：每个事项拥有自己的上下文和消息历史，用户可以创建、查看和切换事项，刷新后仍能恢复。

## 验收

- 后端可以为现有参与者创建就诊事项并按最近活动列出事项。
- 每个事项拥有独立 ID，聊天、历史恢复和操作确认均携带当前事项 ID。
- Web 可以新建并切换事项，切换时加载对应历史，不复用上一事项的消息。
- 桌面与移动端都提供事项入口，错误和忙碌状态可见。
- 后端、前端和浏览器测试覆盖创建、切换与上下文隔离。

## Answer

已完成。API 与 PostgreSQL/In-memory store 支持事项创建和列表；Web 通过当前事项构造聊天传输、恢复历史并支持桌面/移动切换。自动化测试和实际 Docker 浏览器烟测均通过。
