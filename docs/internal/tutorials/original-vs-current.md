## 4. 三类不同的改动

### 4.1 应保留的纠正与场景替换

- 原《重点代码》第 47 行、《技术亮点》第 34–36 行将前置 RAG 放入 API 主链。新版按实际调用说明由 Agent 工具触发；保留辅助函数不证明 API 正在调用它。

- 原客服、技术支持、账单案例换成医院查询、就诊准备和预约。原《简历包装》第 40–79 行的 Java/Spring/BM25 版本不适用于当前工程，应继续排除。
- 原容器名、默认密码、集合名和任意指定的会话 ID 不能直接迁移；新的事项 ID 必须来自服务端，个人报告也不能当公共知识上传。
- 原《带数据指标的加强版简历模板》第 24、40、46、141 行的约 500 条样本、91.3%、RAG 88.7% 等，本次没有核验其原始证据，不能迁入 MediPet。这个判断并不声称原作者伪造数据，只说明它们不构成当前项目的依据。

### 4.2 新增的工程内容

新版的增量已经超出术语替换：

1. 查询、准备方案、显式确认和回执分别对应不同业务状态；Redis `WATCH/MULTI/EXEC` 处理库存与预约，重试使用原回执。

3. 有限分诊、指定药品标签、本地 PDF/图片/OCR，以及当前事项报告追问都有明确事实来源。
4. 回答质量与库存、归属、回执等业务事实分别检查；模型评测保留失败、局部复测和候选状态。

## 5. 两版共同不足，不能算作此次删减

- **异步基础。** 原版有后台画像不阻塞、主辅并行等说明，新版有 `gather`，但均缺少完整时序推导。需要区分事件循环、阻塞 I/O、`redis.asyncio`、Chroma 的 `asyncio.to_thread`、响应前历史写入与响应后的 `BackgroundTasks`。使用 async 并不使所有代码自动并行。
- **练习到答案的闭环。** 新版第 267 行的十道练习很有针对性，但没有逐题最小夹具、运行方法、预期输出、失败结果与答案解释。指向测试文件只能提供入口。
- **深入机制的受控实验。** 缓存、超时、熔断、并行、改写/重排需要可重复实验解释。当前没有独立检索消融或同条件性能对照，不能把机制存在当作收益已测。
- **从空目录实现的课程顺序。** 两版均偏既有项目导读。若目标是自己重写或独立扩展，还需要分阶段编码任务、验收条件和参考实现。

## 6. 简历应该怎样使用这些材料

新版适合作为事实资料库。实际投递应突出两到三个能深入解释、本人确实参与的模块；每条围绕“问题、具体机制、可核验结果”组织，不把组件和测试数字堆成一行。

| 推荐主线 | 可以展开的证据 | 应先确认的本人经历 |
| --- | --- | --- |
| Agent 编排与受限工具调用 | 主辅路由、三次单角色循环、白名单、结构化卡片 | 实际修改过哪些角色、工具、路由或测试 |
| 预约事务与患者事项隔离 | 末号竞争、原回执重试、历史补写、患者过滤 | 是否能重现失败并解释具体校验与状态变化 |
| 业务与模型分层评测 | Judge 高分但业务失败、隔离评测、候选报告 | 是否设计、执行或修复过对应用例 |
| 医疗与报告扩展 | 原文约束、混合 PDF、本地 OCR、同事项追问 | 实际承担的解析、工具、页面或验证部分 |

来源与贡献应分开：三路意图、主辅编排、RAG、分层记忆等是沿用的框架主线；医院事务、患者事项、报告和相应修正是当前工程增量。工程增量也不自动等于用户个人独立完成。被问到架构来源时如实说明基于既有 EchoMind 工程扩展；项目名不需要反复解释来源，但不能把沿用工作改称从零自研。

[现有简历模板](../../../文档+简历/简历包装.md)已有贡献占位项，仍需填成一张“模块—沿用内容—本次修改—本人职责—提交/实验依据”表。AI 辅助实现、本人需求设计、审查、调试和验证应按实际情况描述。

指标采用[证据模板](../../../文档+简历/带数据指标的加强版简历模板.md)的口径：66/66 是固定意图样本；57/58 是完整报告结果项；3/3 是修复后的定点复测。684/21、35、119 属不同验证范围。简历正文选择一条与主张相关的证据即可，其余数字和版本顺序放作品集，不必全部堆入投递版。

## 7. 面试材料应该补到什么程度

当前问答能支持“组件是什么、流程怎样走、权限如何划分”。要支持第二、第三层追问，建议至少做出以下材料：

1. **一份完整请求推演。** 以“给孩子查儿科号源并说明材料”为例，展示绑定身份、意图结果、路由、工具参数、实际卡片、选择、确认回执与历史。真实运行值和教学示意明确区分，不能编造 trace。
2. **两张深入案例卡。** 优先从已有失败中选本人实际复现的案例，例如混合 PDF 只读页眉、无障碍续问没有执行查询。每张写输入、预期、实际、根因、修正、反例、验证范围。
3. **一次事务失败推演。** 分别解释最后一个号被并发抢占、重复确认、事务成功但历史写入失败；画出哪一步改变状态和怎样恢复。
4. **一页方案取舍。** 解释多角色与单角色、Redis 当前实现与其他存储方案、静态 RAG 与实时服务、完整历史与模型上下文各自解决什么问题；替代方案作为讨论，不称当前已实现。

学习完成不以背完模板为标准，而以能否定位入口、解释中间状态、主动举反例、修改一个局部并验证为标准。
