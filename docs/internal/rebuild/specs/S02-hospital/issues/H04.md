# H04 实现持久化号源生成与剩余量查询

## 目标

交付按排班生成、可持久化且不会被再次启动重置的未来七天号源查询。

## 实施范围

- 使用既有 Redis 连接建立集中键构建，按 MediPet 前缀保存号源容量与剩余量。
- 按 H02 排班、`Asia/Shanghai` 和可注入时钟补充未来七天缺失号源。
- 实现科室、医生、日期、时段筛选与稳定排序，输出实际号源 ID 和 `slot_list` 数据。
- 已有号源记录初始化保持原值，查询实时读取剩余量，不使用共享结果缓存。
- 仅为业务存储提供所需读写能力，不扩展为通用仓储框架。

## 输入与输出

输入：H03 服务入口、H02 排班、Redis 依赖。输出：号源初始化与查询方法、存储实现及固定时钟测试；号源消耗和释放由 H06 事务实现。

## 验收

- [x] 固定时钟下生成窗口、日期解释、号源 ID、筛选及排序可重复。
- [x] 无号源与未知科室/医生区分明确，返回数量等于存储真实值。
- [x] 重复初始化及模拟第二次启动保持已改动的剩余量，补充缺失记录而不重置已有数据。
- [x] 号源记录不使用工作记忆 TTL，测试不调用清空全部 Redis 的操作。
- [x] 测试覆盖跨日补充和容量边界；真实 Redis 验证结果与替身结果分别记录。

## 依赖与并行

依赖 H03 已建立的医院服务边界，消费 H02 排班。与 M01/M02 并行；H05 等待本 issue 的实时号源能力。`hospital/service.py`、`hospital/store.py` 由医院支线串行修改。
