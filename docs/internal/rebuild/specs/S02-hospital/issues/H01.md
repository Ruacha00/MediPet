# H01 冻结跨模块契约并建立医院领域模型

## 目标

交付一份 Agent、API、事项存储和页面都能消费的契约及医院领域模型，消除并行任务各自定义业务字段的风险。

## 实施范围

- 对照已导入基准的 Request/Response 结构，确定目录、号源、方案、预约、服务结果模型。
- 固定参与者 `user_id`、患者 `patient_id`、事项 `conv_id` 及服务身份上下文；已有事项以服务端患者绑定为准。
- 固定方案操作、`pending/executed/expired/superseded` 状态、预约 `active/cancelled` 状态、时间与费用表示。
- 定义方案快照、默认 15 分钟期限、执行回执及稳定错误类别，包括缺字段、无号源、身份冲突、失效、改选和可重试并发冲突。
- 在内部契约中列出计划第 10 节接口的请求/响应、artifact 类型/ID/业务 data、历史消息与确认事件形状；保留基准兼容字段。
- 为下游明确本轮结果局部保存、按 ID 去重、确认回执不伪造模型 trace 的约束。
- 固定最近选择列表规则：成功查询替换，空结果清除，失败明确标记不可据旧列表选择；由 A03 工具接入 M02 存储。

## 输入与输出

输入：B04 验收的基准结构、实施计划第 8—10 节。输出：`hospital/models.py`、内部契约文档和可序列化的代表性样例；API、Agent、前端接入留给对应 issue。

## 验收

- [x] 模型覆盖查询、待确认创建、待确认取消、已执行回执和失败结果，字段与内部契约一致。
- [x] 方案同时携带参与者、患者、事项、目标、快照、时间与结果，业务记录可独立序列化恢复。
- [x] 代表性模型测试验证必需字段、状态和时间/费用格式；覆盖无效数据拒绝。
- [x] 契约逐项映射计划接口和七种初始 artifact；如合并类型，记录对应关系及消费者。
- [x] 下游实现可依据样例确定身份来源、列表选择、历史恢复和确认去重行为，无重复会话 ID。

## 依赖与并行

依赖 B04 的真实导入布局与基准测试入口。完成后解锁医院数据、事项模型、Agent 和 API/UI 契约消费；本 issue 只修改模型与文档，不同时改下游模块。`hospital/models.py` 后续字段变更需同步契约消费者。
