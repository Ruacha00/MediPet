# H06 实现创建取消的原子确认与幂等回执

## 目标

交付由确认入口调用的完整业务事务，使重复、并发和失败操作保持预约及号源一致。

## 实施范围

- 校验方案属于当前参与者、患者和事项，处于待执行状态、未过期且目标仍可用。
- 创建事务同步更新方案状态、号源剩余量、预约记录与执行回执。
- 取消事务同步更新预约状态、相应号源与方案回执，避免重复释放容量。
- 重复确认已执行方案返回持久化的同一次结果；冲突返回稳定可重试结果。
- 拒绝过期、已被改选、身份冲突与无可用目标；失败不得遗留半完成记录。
- 输出业务回执及对应 artifact，供 I03 确认接口记录历史；服务本身不伪造模型调用。

## 输入与输出

输入：H05 持久化方案与预约查询、H04 号源存储。输出：创建/取消确认服务、原子存储操作与真实 Redis 验证证据。

## 验收

- [x] 创建前无预约，确认后可查且号源正确消耗；取消确认后状态及号源正确更新。
- [x] 同方案连续和并发确认只产生一次效果，回执及预约 ID 一致。
- [x] 两个方案争用最后一个号源时不超售；冲突后可再次查询实际状态。
- [x] 过期、改选、患者/事项冲突及重复取消均无额外预约或容量变化。
- [x] 真实 Redis 测试证明事务、幂等及并发行为；替身测试单独报告，不作为事务证据。

## 依赖与并行

依赖 H05 的状态、快照与目标引用。可与 M03/M04、Agent 场景适配并行；确认 API 消费本 issue 的服务结果。与 H05 共享医院文件，必须在其完成后实施。
