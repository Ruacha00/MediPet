# H05 实现待确认方案预约查询与改选淘汰

## 目标

交付创建/取消的待确认方案，以及按患者查询预约和改选淘汰旧方案的业务路径。

## 实施范围

- 以服务端身份及真实号源 ID，或 M02 保存的最近结果选择位置，准备创建方案。
- 以当前患者的真实预约准备取消方案；仅准备方案不更新预约状态。
- 将身份、操作、目标、服务生成的展示快照、时间和默认 15 分钟期限保存至方案记录。
- 使用 M02 当前方案引用确保事项最多一个待确认方案；选择变化后淘汰旧方案并保存新引用。
- 实现按当前患者及可选状态查询预约，返回存储事实。
- 含糊确认文本只获得当前方案，不提供无条件创建/取消接口给模型。

## 输入与输出

输入：H04 实时号源、M02 最近选择与方案引用存储、H01 身份契约。输出：准备与查询方法、持久化方案以及确定性状态测试；实际执行在 H06。

## 验收

- [x] 准备创建或取消后，预约记录及号源数量均未发生执行性变化。
- [x] “第一个”等位置只映射本事项最近实际结果；无列表或越界返回明确结果。
- [x] 改选后旧方案标为 `superseded`，当前引用指向唯一新方案；重复读取不产生虚假预约。
- [x] 方案快照、时间、身份可从存储恢复；未知目标、失效及跨患者访问有稳定错误。
- [x] 本人/家属预约查询互不串用，创建与取消准备均有固定时钟测试。

## 依赖与并行

依赖 H04 的实时号源与 M02 的选择列表/当前方案操作；通过其接口消费，避免修改 `memory/visit_store.py`。可与 M03 并行；H06 在本 issue 完成后接管同组医院文件。
