# H02 建立统一医院演示数据与排班内容

## 目标

交付可校验、可复用的单医院演示数据，使业务、知识、页面和评测使用同一组医院事实。

## 实施范围

- 编写明和虚构医院、内科/儿科/眼科、少量虚构医生及公开说明，使用稳定 ID。
- 提供可生成未来七天号源的排班模板、时段、容量和展示费用。
- 编写门诊大厅、收费处、药房、检验科等地点，以及有限起终点组合的普通/无障碍文字指引。
- 编写首次及儿童就诊等预置材料清单、来源标识和人工导诊联系内容。
- 提供本人/家属两名预置患者及演示参与关系，供 M01 初始化使用。
- 明确所有内容均为演示医院数据；时间解释使用 `Asia/Shanghai`。

## 输入与输出

输入：H01 的 ID、模型、时间/费用与来源契约。输出：`hospital/demo_data.json` 及验证内容一致性的测试；运行时初始化由 H04、M01 分别实现。

## 验收

- [x] 数据可通过 H01 模型读取；所有医生、科室、地点、排班引用均存在。
- [x] 医院名、费用、科室、医生、地点及患者关系具有唯一稳定定义。
- [x] 固定日期样例可得到合理排班输入；容量、费用和时段格式有效。
- [x] 文字指引只覆盖预置组合，普通与无障碍模式均有可核对样例。
- [x] 未出现真实个人资料、动态剩余号源快照或已确认的个人预约记录。

## 依赖与并行

依赖 H01 的字段与状态契约。完成后 H03 与 M01 可分别处理医院查询和事项初始化；知识内容编写也消费本文件。后续内容补充集中协调，避免知识与前端各自产生新事实。
