# U03 — 独立患者、事项与完整历史管理入口

## 目标

提供患者选择、事项列表和历史恢复入口，清楚表达当前患者与事项，供 U04 接入后端完整历史。

## 实施范围

- 新增独立 `PatientVisitPanel.vue`，接收患者列表、当前患者、事项列表、当前事项及请求状态。
- 提供患者切换、新事项、事项选择、重命名、归档列表与归档恢复操作，发出语义明确的事件。
- 选择事项发出其真实 `conv_id`，由页面壳读取完整历史；当前项始终显示其绑定患者。
- 归档事项展示恢复入口；恢复完成前不能以其作为继续聊天的活动事项。
- 展示空列表、加载中、失败和修改成功状态；保持组件内输入状态与服务器确认的事项状态区分。
- 外部请求及聊天 messages 更新由 U04 完成；本 issue 只写独立组件和 scoped 样式。

## 输入与输出

- 输入：U01 请求契约样例、I01 实际患者/事项/历史接口样例。
- 输出：患者事项组件、供 U04 消费的事件和状态约定，以及完整历史恢复触发方式。
- 事项不在浏览器中自行换绑患者；修改标题/归档动作成功后展示服务器返回的状态。

## 验收

- [x] 本人/家属选择和各自事项列表可辨认；切换事件包含正确患者 ID。
- [x] 新建、选择、重命名、归档及恢复分别发出对应事件与真实事项 ID。
- [x] 选择旧事项触发读取完整历史，患者标签使用该事项绑定患者，避免仅保留之前的页面选择。
- [x] 归档项显示恢复操作，恢复前不能继续发送；空事项列表有可用的新建入口。
- [x] 标题/归档失败样例保留原服务器状态且显示错误；加载反馈不被展示成空成功列表。
- [x] 组件构建通过，窄窗口下患者和当前事项清楚可读；刷新恢复由 U04/V04 实际验证。

## 依赖与并行

- 等待 U01 和 I01 的契约/实际接口样例，可与 U02 在独立组件文件并行。
- 不修改 App.vue、backends.js 或共享样式；把事件和必要 props 明确交给 U04 统一接入。
- 归档、恢复和身份问题按 I01 服务返回处理，不在前端补造新的业务规则。
