# U02 — 固定业务卡片与确认交互事件

## 目标

将后端 artifacts 作为固定业务卡片展示，并把号源选择与明确确认作为事件交给页面壳执行。

## 实施范围

- 新增职责独立的 `BusinessArtifacts.vue`，按 H01 确认的 artifact 类型显示对应数据。
- 覆盖目录、号源列表、预约/取消方案、预约记录、准备清单、文字指引和导诊联系信息。
- 方案显示操作类型、患者/事项、目标、有效期及服务快照；创建和取消按钮文案可区分。
- 号源选择发出实际号源 ID/列表项事件；确认发出方案 ID 事件；组件本身不发外部请求。
- 消费壳传入的请求中、执行结果及错误状态；过期/被替代的方案不显示可执行假象。
- 使用组件 scoped 样式，布局复用现有视觉基础，不修改 App.vue 或共享请求封装。

## 输入与输出

- 输入：U01 的真实契约样例、artifacts、loading/error 与回执状态 props。
- 输出：固定卡片组件和明确的选择/确认事件，供 U04 接入 API 请求。
- 业务事实完全来自 artifact `data`；不从正文提取医生、号源、费用或预约状态。

## 验收

- [x] 所有约定 artifact 类型可按样例渲染，号源顺序和 ID 对应后端结果。
- [x] 创建/取消方案显示同一服务快照；确认点击仅发出正确方案 ID，不在组件内写预约。
- [x] pending、executed、expired、superseded 状态可辨认；执行中有反馈，重复点击不产生组件内重复状态。
- [x] 空号源、未知地点和业务失败样例显示明确结果，不出现自行生成的可选项。
- [x] 预约记录与准备/指引来源可见；导诊联系只提供联系信息与摘要，不显示已提交给工作人员。
- [x] 组件可被构建导入，窄窗口下文字和确认按钮可读；实际接口点击验收交给 U04/V04。

## 依赖与并行

- U01 样例到位即可开始，与 U03 并行；两者只写各自组件及 scoped 样式。
- 需要改变 schema 时协调 H01/U01；接口未实现时使用明确标注的开发样例验证展示。
- 将 props、事件名与各状态样例交给 U04，App.vue 接入由 U04 单独负责。

- 验证与证据：U02/U03 共 6 项 Node 测试通过，包含样例 SSR、Vue 自定义测试渲染器事件、真实 ID/一基序号、重复点击、失败后重试和状态禁用；两个组件及 scoped CSS 单独 Vite 打包通过，原应用 build 通过。样式在 560px 以下调整为竖排；实际窄屏浏览器核验留 U04/V04，未声称已完成 API 点击。
