# U04 — 页面壳接入聊天、卡片、确认及患者事项

## 目标

在 App.vue 统一连接请求与独立组件，让用户完成患者事项选择、聊天、确认、历史恢复和取消闭环。

## 实施范围

- 接入 U02/U03 组件，统一处理其事件，调用 U01 的请求方法和 I01—I03 真实入口。
- 初始化患者/事项列表；发送聊天时使用当前服务器绑定事项；切换患者进入对应事项。
- 选择号源生成方案，确认按钮直接调用统一确认入口，展示业务回执与相应 artifacts。
- 完整消息来源为后端；刷新、选择旧事项及归档恢复后重新读取文字与卡片。
- 集中更新 App.vue 的异步状态和必要共享样式，保留知识/评测页面结构供 U05 接续。
- 请求返回时核对其所属事项，避免切换后的迟到响应显示到另一患者的聊天区域。

## 输入与输出

- 输入：U02/U03 的 props/事件、U01 客户端、I03 交付的聊天/确认/历史 API。
- 输出：可运行的页面就诊闭环，供 U05 增补详情和 V04 做浏览器验收。
- 业务操作响应按业务回执展示；确认不重新发送自然语言给模型来决定执行。

## 验收

- [x] 页面完成孩子事项 → 查号/材料 → 选择方案 → 确认 → 查询预约 → 准备取消 → 确认取消。
- [x] 只生成方案时无预约，点击确认后有记录；重复点击显示同一回执，错误不会残留为成功卡片。
- [x] 本人/家属切换、事项重命名/归档/恢复均调用真实 API；归档事项恢复前不能继续聊天。
- [x] 刷新及重新选择事项恢复后端全部消息与 artifacts，确认结果和取消回执仍可查看。
- [x] 切换期间的迟到响应按原事项处理，当前聊天、患者标签和选择状态保持一致。
- [x] 空结果、过期、旧方案及患者冲突可理解；前端构建通过并记录一次开发模式实际闭环。
