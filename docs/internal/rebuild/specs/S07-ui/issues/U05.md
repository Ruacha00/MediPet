# U05 — 运行详情、知识与 Skills、监控评测页面整合

## 目标

保留基准管理页面并完成医院场景适配，让普通就诊界面简洁，同时可展开真实运行和评测证据。

## 实施范围

- 默认折叠运行详情，展示实际意图/置信度、主辅角色、路由理由、调用输入/结果摘要和知识来源。
- 成功/失败调用均可核对 trace；业务确认回执单独标记，不伪造 Agent 路由或模型耗时。
- 接续知识导入、查询、统计与来源展示；Skills 列表及主动重载显示后端实际成功/失败结果。
- 适配 V02 的监控/评测数据，展示真实样本结果、失败案例、Judge 失败和基线状态。
- 统一 MediPet 名称、四角色标签及医院示例；普通就诊界面使用用户能理解的功能文案。
- 沿用现有页面和请求方法，不另建后台平台或把运行参数变成普通用户必填项。

## 输入与输出

- 输入：U04 页面闭环、K03 医院知识/Skills 与重载行为、V02 监控评测实际字段/样例。
- 输出：供 V04 浏览器、V06 真实模型及 V07 演示文档使用的整合页面。
- 没有来源、检索失败、Judge 失败均如实展示；未复核结果不自动呈现为已接受基线。

## 验收

- [x] 普通聊天默认不展开技术细节；展开后主辅协作及每个有效工具结果可对应当前请求。
- [x] 成功与失败 trace 都可查，确认回执显示为业务操作且没有虚构模型调用信息。
- [x] 文档导入/查询与空结果/失败状态可操作，来源标识对应 K03 实际数据。
- [x] 修改场景 Skill 并主动重载后，后续请求使用新内容；失败时页面清晰报告。
- [x] 监控和评测页面消费 V02 真实返回，Judge 失败单列，未预填或编造提升数字。
- [x] 全部页面名称、角色标签和默认例句属于 MediPet 医院场景；前端构建通过。
