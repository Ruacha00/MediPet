状态：U01—U05 已完成，32 项前端测试、构建与实际浏览器验收通过；最终全量模型报告展示仍由 V06 保存。界面沿用固定基准 Vue/Vite 实现。

## 计划来源与需求

- 权威范围：[IMPLEMENTATION_PLAN.md](../../../../../IMPLEMENTATION_PLAN.md) 第 10、11.3、14、15、16 节及 P4—P6。
- 主要覆盖：R02—R04 号源与预约闭环、R07—R08 患者/事项/历史、R11 知识与 Skills、R12 运行与评测展示。
- 消费 R01、R05、R06、R09、R10 的后端结果，分别展示目录、准备、指引、协作和导诊联系。
- B04 已交付 Python-only 前端基线；H01 提供字段和错误样例；页面不解析模型正文生成业务事实。

## 边界与职责

保留对话、知识库、评测页面及现有请求封装。主要改动集中于 `frontend/src/App.vue`、`frontend/src/lib/backends.js` 和现有样式；只有业务卡片与患者事项管理因职责独立而拆组件。

API 客户端负责请求与响应映射，App.vue 负责异步请求和页面状态，独立组件通过 props/事件交接展示与用户操作。组件拆分不引入通用 schema 表单、状态框架或新的页面架构。

普通界面使用具体就诊功能名称；运行详情默认折叠。保留唯一 Python 后端及 `/api/python` 前缀，开发代理与容器代理的最终一致性由 V05 验证。

## 必需行为

1. 进入页面后读取预置患者及该患者事项；切换患者后进入对应事项。恢复旧事项时采用服务器返回的原患者。
2. 支持新建、重命名、归档、恢复；归档不丢历史且恢复后方可继续。刷新从后端重新读取完整消息与 artifacts。
3. 固定卡片展示目录、号源、方案、预约记录、准备清单、文字指引和联系信息；有序号源的选择必须对应后端真实结果。
4. 创建与取消方案明确显示操作类型、患者、事项及服务提供的快照，确认事件携带方案 ID，由 App.vue 调用统一确认入口。
5. 请求中提供清晰反馈；重复点击仍消费服务器同一执行回执。过期、旧方案、无结果和冲突有可理解的状态展示。
6. 运行详情能核对意图、主辅角色、路由理由、调用输入/结果摘要和知识来源；确认回执如实显示为业务操作。
7. 保留知识导入/查询、Skills 查看/主动重载和监控评测展示；重载影响后续请求，页面显示真实结果及失败。
