# A04 · 本轮业务结果透传与成功 trace 修正

## 目标

从工具到 OrchestratorResult 返回可信 artifacts 和完整本轮 trace，保留并行有效结果。
供 I02 序列化为 ChatResponse，前端不解析模型正文来重建预约事实。

## 实施范围

- 按 H01 契约贯通工具结果 → AgentResponse → OrchestratorResult。
- 支持 catalog、slot_list、appointment_proposal、appointment_record、visit_checklist、wayfinding、contact_info 的服务结果。
- 修正 `_call_llm` 成功文本返回路径遗漏本轮完整 trace 的问题，同时检查失败返回路径。
- artifacts 与 trace 保存在请求局部对象，不把患者状态挂在复用 Agent 实例上。
- 并行 artifacts 按 H01 稳定 ID 去重；整合器只生成文字，不修改确认快照。
- API 响应序列化、消息落库与页面展示分别由 I/M/U 组负责。

## 输入与输出

输入：A03 工具成功/失败结果，以及多个角色带重复或不同 ID 的业务结果。
输出：文字、角色信息、工具 trace、去重后 artifacts；数据与服务原始快照一致。
同轮同 ID 冲突使用 H01 约定处理并保留可检查证据，不让模型任选一个版本。

## 验收

- [x] 工具成功后正常文本答复仍含本轮全部 trace，数量、工具名、输入和结果摘要匹配。
- [x] 多轮/并发复用同一 Agent 实例时不混入上一轮 trace、方案或另一患者 artifacts。
- [x] 并行相同 ID 只展示一次，不同 ID 均保留；重复不导致一次结果缺失。
- [x] 整合器失败仍返回成功子任务 artifacts，失败子任务状态不被改写为成功。
- [x] 预约方案快照逐字段等于业务服务结果；模型正文声称的虚构预约不生成卡片。
- [x] 无工具调用的普通回复返回合理空结果；业务失败保留失败信息与已有有效结果。
