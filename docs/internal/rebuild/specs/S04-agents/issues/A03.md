# A03 · 医院工具白名单和缓存边界接入

## 目标

让四角色在原工具循环中调用真实医院服务和共享知识检索，模型只能准备预约方案。
保持当前患者事实与动态号源不受公共共享缓存干扰。

## 实施范围

- 保留 AgentToolSpec、make_tool、handler(req, args)，通过工厂或构造参数注入医院服务。
- General：query_hospital_catalog、inspect_request_context；后者不接受身份覆盖参数。
- Appointment：search_slots、list_appointments、prepare_appointment、prepare_cancellation。
- search_slots 返回后调用 M02，把实际有序号源列表写入当前事项；空结果按 H01 约定清除旧选择，查询失败保留失败状态并禁止误用旧列表。
- Guidance：get_visit_checklist、get_wayfinding；按角色需要开放 search_knowledge_base。
- 复用现有共享 RAG 包装与 K02 来源结果；Escalation 保持固定直接响应。
- 公共目录/知识可缓存；号源、患者预约、方案与确认均不走缺少患者上下文的共享结果缓存。
- 最多三次模型请求保持不变；API 生命周期接线由 I02 完成，本 issue 提供可注入接口。

## 输入与输出

输入：已校验 Request、工具 args、H05 服务和 K02 检索依赖。
输出：success、实际业务 data、展示结果和稳定错误类别。
缺失字段、未知目标、无号源、过期/被替换方案沿用服务语义，不伪造成功或内部 ID。
创建和取消的执行方法不注册成模型可无条件调用的工具。

## 验收

- [x] 各角色正确调用其查询/方案工具，输入过滤和返回值可与业务服务直接结果比对。
- [x] 不在白名单的工具名及身份覆盖参数不能触发服务操作。
- [x] 生成创建/取消方案后预约事实不变化；聊天“确认预约”只展示方案。
- [x] 两患者同名查询不返回对方记录；号源变更后下一次查询读取当前事实而非旧缓存。
- [x] 查询后“第一个”映射到刚保存的真实号源 ID；新查询、空结果和失败不会误选此前列表，其他事项的选择保持隔离。
- [x] 普通知识检索保留片段与来源；检索失败和业务 no_slots 等失败类型均可辨认。
- [x] 假模型工具往返、错误参数、最多三次模型请求及原超时/降级机制通过。

## 依赖与并行

依赖 A02 的角色、H05 的服务与方案能力、K02 的检索结果；不使用临时重复服务实现。
编排器与主测试文件由本 issue 独占；mcp/tool_manager.py 在 K02 完成后才编辑。
可与 K03 并行，但双方不改同一测试文件；A04 消费本轮工具结果。
