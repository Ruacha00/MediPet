# A01 · 医院意图实体与分类示例适配

## 目标

让现有三路分类器识别医院业务，修复分类示例未进入实际模型请求的问题。
完成后可在假客户端下独立验证分类与实体，无须业务写入或页面。

## 实施范围

- 增加总计划 7.2 的 12 个业务意图，同步枚举、模板、关键词、分组和细粒度优先规则。
- 保留问候、反馈、投诉、请求、查询、升级和 OTHER 等必要通用类别。
- 技术/账单宽泛类别换成指引/预约；本 issue 不修改角色路由表或最终评测数据集。
- 提取科室、医生、日期、时段、号源/预约编号、起点、目的地、无障碍模式。
- 日期按 Asia/Shanghai 解释今天、明天、后天与明确日期；提供可固定的测试时钟。
- 将已构造的 MediPet 示例插入 `_llm_recognize` 的实际提示词；保留模型接口和算法分支。

## 输入与输出

输入：文本、基准支持的最近上下文及 H01 字段定义；示例包含“明天儿科还有号吗”。
输出：业务意图、原语义置信度及 entities；患者身份不从自由文本覆盖。
投票保留正常 `0.7/0.2/0.1`、关闭向量时的既有分支、LLM 失败降级；不称为校准概率。

## 验收

- [x] 12 个业务意图均有独立确定性样例；细粒度规则优先于宽泛兜底。
- [x] 假客户端捕获的实际请求包含医院示例，不只断言局部变量存在。
- [x] 三路正常、向量关闭、LLM 失败分别验证原投票和降级路径。
- [x] 固定上海时钟验证相对/明确日期，以及“第一个”等上下文实体输入；不凭空生成内部 ID。
- [x] 不存在的科室、缺失日期、模糊表达保留缺失或澄清信息，不编造有效号源。
- [x] 文本自称另一患者不改变 H01 身份；记录实际向量实现类型，不将字符哈希称为远程语义向量。

## 依赖与并行

H01 完成后开始；依赖其字段契约，不等待全部医院业务实现。
输出供 A02 的路由与实体传递使用；同一文件后续由 A05 增加急症共享检查，禁止并行写入。
可与 H02—H06、M 组独立实现并行，不能提前把聊天闭环标记通过。
