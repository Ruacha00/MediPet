# M01 实现预置患者与事项元数据存储

## 目标

交付可被 API 使用的患者关系和事项存储，固定事项所属患者并支持归档恢复。

## 实施范围

- 从 H02 初始化本人/家属及参与关系，仅补缺失记录。
- 按当前演示参与者列出可选择患者；创建事项时校验参与关系。
- 使用 `conv_id` 保存事项标题、患者、归档状态和时间，创建后固定患者。
- 实现按患者及归档状态列表、读取、重命名、归档和恢复。
- 为下游提供统一加载/校验事项身份的接口和明确错误；保留归档事项数据。
- 在本模块集中构建 Redis 键，业务元数据使用持久记录而非工作记忆 TTL。

## 输入与输出

输入：H01 身份与事项契约、H02 预置关系、已有 Redis 依赖。输出：`memory/visit_store.py` 的元数据方法及确定性存储测试；HTTP 入口由 I01 实现。

## 验收

- [x] 两位患者可列出，各事项始终绑定创建时患者，不能通过后续参数改绑。
- [x] 当前参与者只能加载其有效患者关系与事项，未知或冲突身份有明确结果。
- [x] 重命名、归档和恢复只改变相应字段；归档事项默认隐藏但仍能按规则读取。
- [x] 归档状态可供调用层拒绝新消息，恢复后可继续；不存在第二套会话编号。
- [x] 重复初始化保持已有标题、状态及时间，不清空已有事项。

## 依赖与并行

依赖 H01 契约与 H02 预置关系。可与 H03/H04 并行；M02 继承本模块继续追加消息和选择存储。I01 消费身份加载方法，不重复维护患者绑定。

修改前核对：`memory/visit_store.py` 为新模块；源码搜索未发现现有 VisitStore 调用方。只读核对了 H01 Patient/Visit/VisitIdentity、API 入口和医院服务使用方式；图谱刷新由主 agent 统一执行。

实现：VisitStore 接收调用方管理的 `redis.asyncio.Redis`，支持 prefix 与固定 clock。患者存在 `<prefix>patients` hash，仅 HSETNX 补缺；事项存在 `<prefix>visit:<conv_id>` hash，使用 `<prefix>visits:<patient_id>` set 索引；业务键不设 TTL。改名/归档更新只修改允许字段，通过 WATCH 检查并发修改，冲突返回可重试错误；患者绑定和创建时间不改写。

对外交接：`initialize_patients(patients)`、`list_patients(user_id="anonymous")`、`get_patient(user_id,patient_id)`、`default_patient(user_id="anonymous")`；`create_visit(user_id,patient_id,title=None)`、`get_visit(user_id,conv_id)`、`list_visits(user_id,patient_id,archived=False)`、`update_visit(user_id,conv_id,title=None,archived=None)`；`require_identity(user_id,conv_id,patient_id=None,allow_archived=False)`。后两个方法的可选参数为 keyword-only。get_visit 允许读取归档事项，require_identity 默认拒绝归档操作。默认标题为“新的就诊事项”，列表按 updated_at/conv_id 倒序。公开 `redis/prefix/visit_key()` 供后续共享事务，不关闭传入客户端。

错误传递：`VisitStoreError.code/message/retryable` 供 I01 转为 H01 BusinessError detail，工具可转为 ServiceResult；未找到、身份冲突、已归档、无变更字段、无效输入、并发冲突、存储不可用均有稳定类别。不在存储层生成 HTTP 响应。

确定性验证：`.venv/Scripts/python.exe -m pytest -q tests/test_visit_memory.py` 为 **11 passed, 1 skipped**；跳过项为显式启用的真实 Redis 测试。覆盖初始化保留、双患者/参与者隔离、固定绑定、排序、归档恢复、错误类别、并发冲突、bytes 响应、独立前缀及固定时钟。

真实存储验证：以专用 `MEDIPET_VISIT_TEST_REDIS_URL` 指向本机 Redis DB15，仅运行 `-k real_redis`，结果 **1 passed, 11 deselected**。使用随机 `medipet:test:m01:<uuid>:` 前缀，核验新 Store 读取原记录、重复初始化、改名/归档/恢复和全部 3 个元数据键 TTL=-1；结束只删除该前缀，未读取 .env、未执行全库清理。

验收边界：此处是元数据算法与真实 Redis 元数据存储证据；没有验证完整历史、Chroma、模型或 API。M02/I01 后续消费本接口。
