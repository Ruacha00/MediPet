# M04 实现工作记忆失效后的历史恢复与多轮承接

## 目标

交付在工作记忆压缩或过期后仍能继续同一事项的上下文恢复机制。

## 实施范围

- 工作记忆缺失时，由 M02 当前事项完整消息恢复最近窗口，不加载其他患者历史。
- 超出窗口的内容继续沿用已有摘要和情景召回，避免每轮把全部历史塞入模型。
- 结合最近消息与 M02 实际选择列表提供“第一个”“明天呢”“还是下午吧”的承接上下文。
- 恢复当前方案引用及展示信息，方案能否执行仍由医院服务验证。
- 归档恢复后继续原事项和原患者；恢复记忆不重新执行历史工具或确认操作。
- 将完整历史中的业务结果视为历史快照，实时号源和预约仍需业务工具查询。

## 输入与输出

输入：M03 的患者隔离记忆、M02 完整消息/选择状态。输出：可由 I02 调用的恢复入口、窗口与承接上下文测试。

## 验收

- [x] 最近工作记忆过期后能恢复本事项窗口，完整历史与卡片数量不减少。
- [x] 压缩前后患者范围不变，窗口外信息按已有摘要/情景路径处理。
- [x] 两患者交替继续事项时，指代及列表位置不会引用对方结果。
- [x] 归档后恢复仍绑定原患者，当前方案引用正确且不隐式执行。
- [x] 假模型或确定性输入验证承接所需上下文，区分存储恢复证据与真实模型理解效果。
- [x] 实际 Redis/Chroma 下验证过期/恢复路径，记录真实结果而不以源码阅读替代。

## 依赖与并行

依赖 M03 隔离逻辑并消费 M02 历史接口。与 H06、知识内容、前端独立组件可并行；I02 接入本入口后才验收聊天级恢复。与 M03 共享文件，顺序合入。

## 完成记录

负责人：主 agent，延续 M03 影响分析。`get_context(identity,query)` 先核对事项固定患者和归档状态；窗口缺失时从该事项完整历史恢复最多 WORKING_MAX 条，达到压缩阈值时仍使用原摘要/情景路径及最近五条规则。

- 窗口恢复使用 WATCH 防止覆盖并发恢复/写入；竞争后读取已有窗口，不重试循环，不执行历史工具。消息元数据保留原 artifact，完整历史没有删改。
