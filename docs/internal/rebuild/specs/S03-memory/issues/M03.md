# M03 为工作情景及画像记忆增加患者作用域

## 目标

交付保留基准记忆机制、但不会混用本人和家属上下文的 Redis/Chroma 记忆实现。

## 实施范围

- 扩展记忆调用的已验证身份上下文，Redis 工作记忆及摘要按参与者、患者、事项隔离。
- 保留最近消息 TTL、压缩、情景召回及画像算法，在 Chroma 存取加入患者字段与过滤。
- 情景先查当前事项，再同一患者其他事项，移除仅按参与者覆盖全部患者的回退。
- 区分当前患者明确资料与参与者表达偏好；画像仅保存明确提供信息。
- 使用 MediPet 独立情景/画像集合，避免旧业务数据混入；不迁移旧项目个人记录。
- 接收 H01 身份结构，供 A02 Request 与 I02 聊天接入传递，不在模型工具参数中接收身份覆盖。

## 输入与输出

输入：M02 事项与历史接口、H01 身份契约、基准 MemoryManager。输出：患者作用域记忆方法、过滤测试和真实组件验证记录。

## 验收

- [x] 同一参与者本人/家属、同一患者多事项的 Redis 隔离符合约定。
- [x] 当前事项无情景结果时，仅回退到当前患者其他事项。
- [x] 画像保存明确资料且患者信息与表达偏好分开，推断病情不成为事实。
- [x] 压缩和 TTL 机制仍可运行，M02 完整历史不受影响。
- [x] 真实 Redis/Chroma 验证实际过滤及字段行为；替身测试不能单独满足此项。

## 依赖与并行

依赖 M02 的患者事项关系与历史职责划分。按 H01 接口可与 H05/H06、A02 和 I01 开发并行；I02 集成时统一传递身份。与 M04 共享记忆实现和测试，必须顺序实施。

## 完成记录

主 agent 实施。GitNexus MemoryManager/get_context 上游 LOW；源码核查发现 API chat 和 CLI 的旧参数调用，I02 将统一接入 VisitIdentity。本模块不再接受只有 user_id/conv_id 的无患者调用，防止不完整身份回退。压缩保留最近五条的原算法不变，同时修正基准重写列表时反转了时间顺序的问题。

- 公开 `add_message(identity,role,content,metadata=None)`、`get_context(identity,query="")`、`update_profile(identity)`；身份为 VisitIdentity。构造可注入共享 redis_client、chroma_client、visit_store；只有自建 Redis 客户端由 close 关闭。
- 工作键/摘要键使用 MediPet 前缀加 user/patient/conv；默认集合 medipet_episodic、medipet_profiles。Chroma 使用实际支持的 `$and`，同患者其他事项回退加入 `$ne` 当前事项，按当前→其他排序去重。
- 画像分别持久化患者资料与参与者表达偏好，只接受最近用户消息中逐字可核对的原句，拒绝模型合成疾病、助手陈述及没有证据的偏好。未重写 SDK 或检索/压缩框架。
- 23 项记忆及事项定向测试通过；其中记忆专组为 3 项替身、3 项真实 Redis/Chroma，涵盖本人/家属、同患者多事项、实际过滤、TTL、压缩顺序和画像字段。真实模型用确定性客户端替代，不声称模型理解已验收。
- 真实 Chroma 0.5.23 HTTP 模式、默认客户端 embedding；每例唯一集合/Redis DB15 前缀并定向清理，证据 `.scratch/M03-tests.xml`。后续 M04 验证完整历史恢复。
