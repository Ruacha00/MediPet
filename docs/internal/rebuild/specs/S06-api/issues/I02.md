# I02 — 聊天接通记忆、历史、artifacts 和急症前置

## 目标

使 `/chat` 使用服务器确认的患者与事项，按既有主流程生成答复，并将文字、业务卡片和完整历史贯通。

## 实施范围

- 消费 I01 的身份加载；ChatRequest 保留原字段，支持新事项 `patient_id` 及无事项时的默认患者兼容路径。
- 在既有生命周期创建并注入医院服务、事项存储与知识依赖，接入幂等初始化；沿用既有知识和 Skills 管理接口，将 K02/K03 产物接到实际调用入口。
- 身份/归档验证后调用 A05 共享急症检测，命中时跳过普通记忆召回、意图模型和一般 Agent 执行。
- 普通请求通过 M04 恢复/读取工作记忆，将患者与事项上下文传给编排器。
- 把 A04 经 A05 交付的本轮 artifacts、完整 trace 和角色/路由信息映射到 ChatResponse。
- 保存用户消息和最终响应的完整记录，更新工作记忆；急症固定响应也进入当前事项历史。
- 只处理接入映射；不重写意图算法、工具循环、记忆存储或急症规则。

## 输入与输出

- 输入：I01 身份入口、A05 完整编排结果、M04 历史恢复接口、K03 已接入的场景内容。
- 输出：H01 契约下的 ChatResponse、历史条目及 UI 所需实际响应样例。
- 并行角色返回的业务事实沿用上游去重结果；模型正文不参与生成预约快照或补造 artifacts。

## 验收

- [x] 指定事项请求使用绑定患者；传入冲突患者返回错误；无事项的兼容调用返回新事项信息。
- [x] 归档事项拒绝新消息；恢复后可继续，且读取到原历史。
- [x] 假模型的复合查询保留主辅角色、工具 trace 和两类结果；失败分支未被标记为成功。
- [x] 急症命中时将普通记忆/模型调用设为会抛错的替身，接口仍返回固定响应与可恢复历史。
- [x] 否定表达和一般咨询反例走普通路径；文字“确认预约”只展示方案，不执行写预约。
- [x] 压缩或工作记忆过期后同一事项可继续；本人/家属消息、最近选择及 artifacts 不串用。
- [x] 启动可读取医院/知识数据，重复初始化不覆盖既有记录；知识导入/查询接口和 `/skills` 可消费新内容，`/skills/reload` 后下一次 chat 使用更新文本。
