## 边界与输入

沿用 FastAPI、生命周期依赖注入和普通 JSON 响应。消费已完成的医院服务、事项存储、工作记忆、编排器和 Skills。API 只处理请求映射、身份加载、调用和响应，不复制 Redis 键构建或预约事务。

保留计划第 10.1 节已有接口；新增患者、事项、完整消息和统一方案确认入口。继续使用演示参与者上下文，本 spec 不引入登录、真实医院接入或新的会话编号。

## 必需行为

1. `/patients` 只返回当前参与者可选患者；事项的 `conv_id` 创建后固定患者。读取、更新、聊天、确认均从服务器加载事项关系。
2. `/visits` 支持创建、患者/归档筛选、重命名、归档与恢复；`/visits/{conv_id}/messages` 返回完整消息及 artifacts。归档不删除消息，恢复后才可继续发送。
3. `/chat` 保留旧必需字段。无事项的演示请求可创建默认患者事项；已有事项若显式传入冲突患者则返回明确错误。
4. 身份及事项状态验证后，使用 A05 的共享急症检测；命中时跳过普通记忆召回和模型调用，返回固定响应并保存历史。普通流程使用 M04 的恢复逻辑。
5. ChatResponse 保留路由、角色、工具、延迟等字段，增加服务器解析的患者/事项信息和本轮 artifacts；业务事实只来自服务和工具结果。
6. 确认入口同时处理创建和取消，直接调用 H06 业务事务；成功、失效、旧方案、患者不符和并发冲突按 H01 返回。
7. 确认回执及相应 artifacts 写入当前事项完整历史，标记为业务操作结果；重复请求返回同一执行结果，不构造虚假的模型 trace。
