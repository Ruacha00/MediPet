# K02 · 医院知识初始化与来源失败透传

## 目标

将医院短文档接入现有 RAG，保留来源和真实失败状态，重复启动不重复导入。
为 A03 的共享知识工具提供稳定输出。

## 实施范围

- 替换基准默认业务文档，导入 K01 固定 ID/标题/来源，初始化只补充缺失内容。
- 使用 B 组配置的 MediPet 专用 Chroma 知识集合/数据空间，不沿用旧场景知识集合。
- 沿用既有切片、查询改写、多查询并行召回、去重和重排；适配提示词与领域示例。
- 片段保留文档 ID、标题、来源和实际重排信息；失败状态沿既有结果链返回。
- 只为确有必要的接入修改工具管理器；缓存、超时、熔断、降级算法不重写。
- `/search`、文档导入和统计等既有管理入口保持能力；API 接线归 I 组，不同时编辑 api/main.py。

## 输入与输出

输入：K01 文档、查询文本/top_k、B04 可运行的知识依赖与配置。
输出：真实检索片段和来源，或无结果/模型失败/检索失败的可辨认结果。
普通 RAG 仍由 Agent 选择共享工具进入，不改成每条消息强制先检索。

## 验收

- [x] 首次初始化可检索医院流程，重复初始化后文档 ID/数量不增加重复项。
- [x] MediPet 集合中不含旧业务默认材料，来源可定位 K01 具体文档。
- [x] 多查询合并去重和重排仍生效，工具返回保留标题、来源和真实处理信息。
- [x] 无匹配结果、改写模型失败、检索异常分别保留实际状态，不伪造相关片段。
- [x] 动态号源/个人预约问题不会从静态文档产生当前业务事实。
- [x] 假依赖测试覆盖成功和失败；记录真实 Chroma 验证待 V03 执行，不以替身证明持久化。
