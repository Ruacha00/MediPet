# K03 · 四组场景 Skills 匹配与主动重载

## 目标

为四角色提供与医院数据一致的场景规则，并保留显式重载后后续请求生效的行为。
Skill 只注入提示词，不能代替程序权限和预约校验。

## 实施范围

- 创建 general_visit、appointment_assistance、visit_guidance、service_boundaries 四个目录及 SKILL.md。
- 替换或移除导入的旧场景 Skill，使加载器扫描范围和列表只包含本项目当前有效内容。
- 使用已导入加载器支持的元数据、A02 角色名称和医院领域关键词，不新增自定义解析格式。
- 覆盖公开信息澄清、号源选择与确认边界、材料流程与文字指引、人工联系/急症和服务范围。
- 需要始终生效的角色边界使用无关键词的对应 Skill；不要依赖偶然关键词匹配。
- 保留文件加载、角色/关键词匹配、注入和主动 reload；不重写匹配算法或增加自动文件监听。
- 对外入口仍为 `/skills` 与 `/skills/reload`；API 接线和浏览器入口由 I/U 组负责。

## 输入与输出

输入：A02 最终角色、K01/K02 医院事实与来源、现有 Skill 文件元数据格式。
输出：四组可列出、可匹配、可注入的 Skill；主动重载后新请求使用更新内容。
通用边界持续生效，场景关键词只控制可选细节；身份和工具执行权仍来自程序。

## 验收

- [x] 四组文件均可加载且元数据角色有效，Skill 列表描述为具体就诊功能。
- [x] 扫描和注入结果没有旧技术支持/账单场景文件，旧内容不与新规则同时生效。
- [x] 正例匹配正确角色/关键词；无关角色或关键词不错误注入场景细节。
- [x] 不含任何场景关键词时，对应角色的常驻边界仍有效。
- [x] 修改测试副本后不自动生效；调用现有 reload 后后续加载/注入使用新文本。
- [x] Skill 不要求创建第五个 Agent、不承诺真实转人工、不把含糊确认文本当成执行事件。
- [x] 与知识和业务事实核对一致；元数据/匹配/重载测试通过，API 和页面验收仍由 I/U 组记录。

## 依赖与并行

依赖 A02 的角色名和 K02 完成后的知识测试文件；与 A03 可并行。
本 issue 不编辑 agents/agent_orchestrator.py 或 api/main.py，避免同时抢写调用链。
若现有注入行为必须由角色提示词修正，交 A 组写者按依赖合入后再验收，不复制另一套注入机制。
