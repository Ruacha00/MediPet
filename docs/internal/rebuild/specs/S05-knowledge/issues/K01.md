# K01 · 编写统一医院事实的知识短文档

## 目标

为“明和虚构医院”提供 12—20 份短文档，供既有知识库导入与检索。
文档应可独立审阅，静态事实能与演示数据逐项核对。

## 实施范围

- 覆盖医院介绍，内科/儿科/眼科公开说明，预约流程、取消规则、首次/儿童就诊材料。
- 覆盖报到、缴费、取药、检验等计划内流程；可按主题拆成便于切片的短文档。
- 每份使用固定文档 ID、标题、来源标识；避免同一主题多个无版本含义的重复副本。
- 医院名、科室、地点、费用和其他共享静态事实以 H02 数据为准，不另造一份冲突医院。
- 说明信息不足时需要补充的材料或使用的查询入口，不作诊断或用药建议。
- 不把医生实时排班、剩余号源、个人预约记录固化为知识事实；精确方位由指引工具返回。

## 输入与输出

输入：H02 的 hospital/demo_data.json、总计划既定范围和 H01 来源字段约定。
输出：knowledge/ 下 12—20 份可被 K02 导入的文档，以及文档内完整元数据。
内容为虚构医院演示资料；不引入真实医院数据抓取、医学资料研究或额外产品需求。

## 验收

- [x] 文档数处于 12—20，计划主题均有对应短文档，ID 和标题稳定且唯一。
- [x] 每份有可在结果中展示的来源；来源实际对应本地演示资料。
- [x] 对医院、科室、地点、费用等共享事实逐项核对，未与 H02 相矛盾。
- [x] 预约与取消文字明确先准备、再点击确认，不描述聊天语句即可完成写入。
- [x] 准备材料与儿童场景可形成 R05 检索样例；未知项目不补充未配置事实。
- [x] 扫描不含旧客服业务、真实个人信息、动态号源或未经实现的诊疗能力声明。

## 依赖与并行

依赖 H02 的统一事实；H01 契约通过 H02 继承。
只写 knowledge/，可与 H03—H06、A/M 组并行；K02 后续导入，不在本 issue 修改加载器或 API。
如果核对发现业务事实缺项，记录并交给 H02 写者补充，避免双写 demo_data.json。

## 完成记录

主 agent 完成 knowledge/ 下 **17 份 Markdown**，固定 frontmatter 为 doc_id/title/source_id/source；source 指向真实本地文件。覆盖医院与三科室、预约/取消、一般/首次/儿童材料、报到、缴费、取药、检验、无障碍、患者事项、导诊及演示费用。

元数据检查：数量17、ID与标题唯一、source文件均存在。内容对照 H02：医院/门诊时间/地址、3医生/科室楼层、14条指引所涵盖的7对地点、材料、联系信息和1500/2000分费用一致。预约/取消均要求按钮确认；没有保存实际医生出诊日期、余量、个人预约状态。旧品牌/技术客服/物流订单等内容扫描无匹配。本文记录内容与元数据核对，检索运行由 K02/V03 验证。
