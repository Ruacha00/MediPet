# V02 适配评测执行与结果记录

## 目标

让既有评测与监控输出反映 MediPet 真实请求上下文和失败结果。

## 实施范围

- 沿用 Accuracy、Macro-F1、四维 Judge 与基线比较，评测 Request 带入患者/事项上下文。
- 保留编排器直接评测，业务确认闭环由 I04 的 API 断言覆盖；Judge 失败单列。
- 检查监控的路由/工具/检索/延迟和项目命名，按实际经过的组件记录结果，不增设指标治理框架。

## 输入与输出

输入：V01 数据、A05 编排结果和 M04 记忆作用域。输出：可执行评测器、结果格式和监控字段，供 U05 展示。

## 验收

- [x] 用假模型跑通成功、调用失败及 Judge 失败路径，失败不混入有效质量得分。
- [x] 不同患者和事项的评测输入保持隔离，直接编排与 API 业务验收职责清楚。
- [x] 未复核报告不会覆盖已接受基线；已有路由惩罚/工具状态统计机制保持可用。

## 依赖与并行

可与 I01—I04、前端组件并行；独占评测器与监控代码，案例数据由 V01 先交付。

依赖以文件头的 `depends_on` 为准；共享路径是计划写入边界，开始前按当前源码复核。执行规则见[工作索引](../../../README.md)。
