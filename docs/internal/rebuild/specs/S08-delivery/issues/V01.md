# V01 编写医院意图、多轮与边界评测集

## 目标

提供独立于提示词示例、可复用的医院评测输入与业务预期。

## 实施范围

- 为 12 个主要意图各准备至少 4 个不同表述，另含通用/模糊输入；记录标签与预期角色。
- 准备至少 12 组多轮对话及 8 组边界，涵盖确认、改选、双患者、无结果、检索失败、否定表达与急症。
- 引用 H02 的医院事实，使用固定时钟和预置患者；多轮案例写明前置状态与预期业务变化。

## 输入与输出

输入：H02 稳定演示事实与 A01 意图标签。输出：场景数据及可供 API 测试复用的预期结果。

## 验收

- [x] 主要意图不少于 48 条、多轮不少于 12 组、边界不少于 8 组，标签均有效且含通用兜底。
- [x] 评测措辞与提示词训练式示例分离；号源、地点、费用及患者引用均可核对。
- [x] 每个业务边界有确定性状态断言，未使用 LLM Judge 代替预约事实校验。

## 依赖与并行

数据独占 evaluation/cases/；可与业务/API/UI实现并行，变更标签需先同步 A01。

依赖以文件头的 `depends_on` 为准；共享路径是计划写入边界，开始前按当前源码复核。执行规则见[工作索引](../../../README.md)。

## 完成记录

主 agent 完成 evaluation/cases 的三个 JSON 与使用说明：54 条意图（12×4+6通用）、12 多轮、12 边界。已运行数据检查：ID 唯一、IntentCategory 标签全部有效、12类各4条、去除末尾标点后与当前提示词模板无重复。

医院名、患者 ID、科室/医生/地点、日期与 H02 对应；引用最近列表取目标，无伪造运行编号。患者切换、归档和确认用 setup/between_turns/after_turns 显式标注驱动动作，避免把身份切换或确认交给聊天文字执行。

每组包含业务状态断言和前置说明。此 issue 仅证明输入就绪，尚不代表模型评测或事务边界已运行；V02/I04/V03/V06 分别消费并记录真实证据。
