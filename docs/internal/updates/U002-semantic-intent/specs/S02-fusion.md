# S02 三路融合、缓存与降级

归属：[U002 计划](../plan.md)。任务：03、04。细节以[契约](../contracts.md)为准。

## 交付

接通主聊天、意图评测、隔离业务评测三个创建入口，共享编码资源并隔离识别器可变状态。保留正常融合权重和路由结构，模板按空间/版本完整构建，输出实际后端诊断，修正故障时无门槛采用向量的行为。

## 验收

- 现有 LLM、关键词、实体、日期、急症保护与正常权重回归通过；DeepSeek 配置不被当作 embedding 配置。
- 并发首请求只构建一次模板；learn 与推理重叠时旧模板/旧分类不重新进入缓存；两个识别器学习状态不串用。追加模板后仍可按冻结门槛参与正常融合，但要标记校准模板已变化，LLM失败时不能仅凭该向量定类。
- 512 维语义模板与 256 维哈希查询绝不混比；同维度但模型指纹不同也拒绝。故障转移后使用完整哈希模板；哈希失败时向量弃权。
- 不同后端、模板、校准版本的分类缓存相互隔离；前 200 字相同而后文不同的消息不碰撞。保留日期和实际历史输入的区分。
- 正常、仅 LLM 失败、仅 embedding 失败、两路失败、弱相似、强信号冲突、未校准、超时、关闭向量均有可读的确定性测试。
- top1 与第二名分差来自不同类别；哈希不再凭正分单独越过关键词。普通低置信度走 OTHER；急症固定响应不等待编码器。
- API 旧响应字段保持兼容；新增诊断及评测元信息反映真实运行，不把 hash fallback 标为 semantic。

## 测试边界

用假 embedding 验证融合控制流，用真实模型验证表示质量。API/编排器的业务状态仍由现有测试断言，不能用 LLM Judge 或相似度替代身份、确认和事务断言。
