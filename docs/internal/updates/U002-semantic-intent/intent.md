# U002 中文语义意图向量接入

日期：2026-09-17。状态：准备实施，当前仅完成方案与任务拆分。

## 用户意图

保留现有 LLM、向量、关键词三路融合架构，将意图向量分支接入适合中文的语义 embedding 模型，把字符哈希保留为明确的降级方案。承接原教程的架构与讲解顺序，在原有实现上改进。

## 当前问题

`core/intent_recognizer.py` 默认把字符 1/2/3-gram 映射到 256 维哈希向量；它主要提供字面线索。当前聊天 SDK 不提供实际 embedding 编码器。替换成真实模型还必须处理模板和查询混用向量空间、首次并发加载、缓存失效，以及 LLM 失败时任何正相似度都被直接接受的问题。

## 本次范围

1. 首选本地 `BAAI/bge-small-zh-v1.5`，FP32 ONNX 推理；模型导出、依赖兼容性与效果由独立任务验证。DeepSeek 继续负责现有 LLM 分支，无需新增 embedding API 密钥。
2. 明确语义、哈希和关闭向量三种运行模式，记录实际后端与降级原因；语义和哈希各使用自己的完整模板向量。
3. 保留正常融合权重 `0.7/0.2/0.1`、关闭向量时 `0.85/0.15` 及正常融合阈值 `0.5`。单独修正 LLM 故障分支，并按独立开发集校准向量接受门槛。
4. 完成独立中文数据集、分支对照、故障矩阵、真实 embedding 与 DeepSeek 验证；学习、简历和面试资料沿原章节增量更新。

本轮交付是计划、契约、spec、原子 issue 和执行检查点；不将其记为模型已接通。现有聊天模型、六角色、急症前置、预约确认、患者事项边界保持有效。知识库和记忆的 Chroma 向量不在本次迁移范围；不新增远程 embedding 服务、模型训练、向量数据库或通用供应商平台。
