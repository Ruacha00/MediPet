# U003 前端优化计划

依据：[更新意图](intent.md)。用户已授权实施；任务进展见各issue与EXECUTION.md，源码完成不代表8088部署已更新。

## 1. 已核对的现状

核对范围：`frontend/src/App.vue`、全局样式、四个业务组件、API适配层、现有前端测试，以及浏览器中`http://127.0.0.1:8088/`的现有对话页面。浏览器只做读取，未发送聊天、确认预约、上传或运行评测。当前打开的历史对话不证明容器已部署最新源码；实施验收必须核对构建版本。

| 项目 | 实际情况与依据 | 计划处理 |
| --- | --- | --- |
| 顶栏头像 | `App.vue`的`avatar-button`没有点击处理 | 删除，不补造账户功能 |
| 顶栏Python标签与API文档 | 技术标签和真实文档链接；不帮助就诊决策 | API文档移到管理入口，普通页只保留简洁连接异常提示；不把health正常解释为模型健康 |
| 大标题与装饰 | 已有事项时仍显示宣传标题、介绍，占用工作区高度 | 压缩为简洁页头，演示标识保留一次；去掉无信息装饰 |
| 三个一级页签 | 对话、知识库、评测目前同级；后两者有真实功能 | 默认就诊工作区，另设次级“管理与调试”入口，不删除已有功能 |
| 回复排版 | `App.vue`使用`<p>{{ item.content }}</p>`；浏览器能看到`**`与表格原文 | 支持受控Markdown段落、列表、强调、表格和链接；不改写原回答事实 |
| 当前就诊人和事项 | 左侧与对话栏重复呈现，事项标题多为“新的就诊事项” | 当前身份清晰固定；列表紧凑化，保留时间、选中状态和重命名/归档；不凭空生成诊断式标题 |
| 列表滚动与窄屏 | 当前桌面有左右内部滚动；样式包含固定高度和多层overflow | 精简滚动层级，窄屏用事项抽屉；具体遮挡问题需在目标尺寸验收，不先宣称现有移动端已失败 |
| 运行详情 | 侧栏及每条回复已有折叠，但占据患者流程且重复 | 普通页保留简洁资料来源；工程字段集中到按请求查看的调试区域 |
| 卡片信息 | 号源、方案、回执、取消均有实际事件/接口；编号与同一方案在历史中反复展示 | 优先显示办理信息和当前状态；内部ID及历史版本折叠，完整记录仍可访问 |
| 异常提示 | `chatError`同时传入每条业务卡片，可能重复出现在多个历史位置 | 错误按当前操作呈现，能定位到相应卡片；不覆盖无关历史卡片 |
| 发送与历史刷新 | 发送立即清草稿，回读权威历史后更新；`readHistory`每次滚到底 | 展示未完成发送状态；阅读历史时不强制跳底，提示“有新消息”；区分失败、待核对和已完成 |
| 报告上传 | 已支持PDF/图片与大小检查；文件input使用`display:none`，标签无键盘触发处理 | 改为可聚焦且有名称的真实上传入口，清楚显示处理状态/错误；保留既有约束 |
| 示例与首屏请求 | 空白页示例包含固定“孩子/儿科”；挂载时同时读监控、Skills、知识统计 | 示例不预设就诊人身份；管理数据进入对应区域再加载，失败不干扰聊天初始化 |

当前确认的无动作控件主要是头像按钮，不能把所有静态说明或真实管理功能都归为“无功能”。保留状态、来源和演示说明，是为了帮助正确操作。

## 2. 目标页面结构

```text
MediPet · 就诊助手                         管理与调试
演示医院 · 不提供诊断
┌ 就诊人 / 事项列表 ┐ ┌ 当前就诊人 · 当前事项 ─────────┐
│ 选择本人或家属    │ │ 消息、号源、方案与办理结果       │
│ 新建事项          │ │                                │
│ 进行中 / 归档     │ │ 出错时给出原因和下一步           │
│ 事项名称与时间    │ ├───────────────────────────────┤
│ 重命名 / 归档     │ │ 上传报告 · 输入问题 · 发送       │
└─────────────────┘ └───────────────────────────────┘
```

手机端：顶栏保留当前就诊人/事项与“切换”按钮，列表进入可关闭的抽屉；输入区在可见范围内，正文为主要滚动区域。抽屉支持Esc关闭、焦点返回；切换上下文仍使用既有请求版本隔离。

次级入口包含知识检索/导入、Skills、监控、评测和API文档。页面清楚标注管理用途，返回就诊后保持当前事项、已有草稿及阅读位置。暂不引入前端路由库或复杂状态框架。

## 3. Spec与验收要求

### S01 信息层级与工作区

- 默认进入就诊工作区；顶栏无无动作头像、技术栈宣传或虚构计数。
- 患者、事项、消息和办理卡片优先。压缩宣传区域与重复说明，保留演示标识、急症提示及资料来源。
- 管理与调试均可到达并可返回；工程细节默认不打断就诊，管理数据按需读取。
- 沿用当前色系；主要正文约16px、辅助文字原则上不小于13px，关键动作有明确名称与焦点状态。触屏主动作目标至少44px高。

### S02 消息、卡片和操作反馈

- Markdown只用于阅读：禁用原始HTML，限制链接协议，不加载模型提供的远程图片；表格允许局部横向滚动。不能使用未经处理的`v-html`直出模型内容。
- 方案与回执以结构化服务数据为准。患者、科室、医生、时间、费用、地点、状态和确认操作保持可见；内部ID、完整JSON及重复方案版本按需展开。
- 仅待确认且有效方案能执行；已执行、过期、替代、取消和库存变化有明确状态。聊天文字、快捷示例或Markdown链接均不能绕过卡片确认。
- 发送、上传、确认和取消分别有真实的忙碌/成功/失败反馈。不展示虚构百分比、Agent逐步思考动画或没有对应协议的“停止生成”按钮。
- 网络中断后不能把未知执行结果显示为未执行或自动再次提交。先读取权威状态；无可核对状态时明确提示，保留既有防重约束。
- 上传输入可由键盘操作；选择格式错误、超过10MB、识别失败均有就地提示。PDF最多10页等服务端限制仍以服务校验为准，不靠页面文字替代。
- 空白页保留少量可真实使用的示例，点击只填入草稿；不默认把当前就诊人当儿童或代替用户发送。

### S03 验证与可维护性

- 抽取少量独立展示组件，优先复用现有`PatientVisitPanel`、`BusinessArtifacts`、`HealthArtifacts`、`ReportUpload`。不把本轮变成全面拆分App或更换框架。
- 全局样式仅在完成组件引用核对后删除无用规则，不因“看起来没用”删掉错误态、隐藏面板或窄屏样式。
- 测试覆盖真实事件与状态变化，避免只检查源码字符串或截图像素就认定功能可用。
- 分别记录组件/接口替身验证、真实API/存储验证和浏览器可用性；假数据不能冒充真实模型或业务验收。

## 5. 验收场景

| 场景 | 期望 |
| --- | --- |
| 初次进入、患者/事项为空、接口失败 | 下一步明确；不能空白或永远加载；重试入口确实读取对应数据 |
| 本人与家属切换、历史恢复、归档/恢复/重命名 | 内容、草稿策略和操作对象明确；在途响应不串入其他事项 |
| 长回复、列表、Markdown表格、长编号 | 正文可读，容器不撑破视口；无危险HTML执行 |
| 查号→选号→准备方案→显式确认→回执 | 每步状态清楚，未确认不显示预约成功，防重复提交保持有效 |
| 准备取消→确认取消；方案过期/被替换/无库存 | 取消仍需明确确认；错误定位到当前动作，不污染全部历史卡片 |
| 文字报告、PDF/图片上传、格式或大小错误 | 支持方式与当前能力一致，能识别处理中/失败/完成，内容绑定当前事项 |
| 断网、服务端错误、办理成功后历史读取失败 | 不伪造成功，不丢失可恢复输入；未知业务状态先核对而非盲重试 |
| 阅读历史时收到新结果 | 保留阅读位置并提供跳至新消息入口；用户主动发起新消息可跟随到底 |
| 管理与调试进入/返回 | 搜索/导入/Skills/监控/评测功能保留；不因进入页面自动启动模型评测 |
| 键盘Tab/Shift+Tab、Enter、Esc | 上传、发送、切换、确认均可达；焦点可见、无陷阱；输入快捷键有提示并兼容中文输入法组合态 |
| 360×800、768×1024、1440×900与200%缩放 | 无整页横向溢出；当前身份与主要操作可找到；长表格仅在自身区域滚动；软键盘遮挡需真实移动环境另核对 |

实施前记录基准：可点击却无行为的控件数、常用任务操作路径、指定尺寸下主操作是否被遮挡、管理请求是否在首页触发。完成标准以这些可复核事实和场景通过为准，不预写“效率提升百分比”。

## 6. 实施与交付边界

- 开工前执行当前树的GitNexus上游影响分析，重点核对`sendMessage`、`readHistory`、患者/事项切换、`confirmProposal`及卡片事件链；HIGH/CRITICAL影响先说明，图谱缺口结合源码与测试补核。
- 不改变API路径、患者身份规则、预约显式确认、幂等回执或服务端状态判定。若发现前端无法独立解决的问题，记录证据后单列范围；不顺手改模型提示词来缩短回答。
- 常规前端测试和构建先行；真实业务回归使用隔离测试事项/环境。复用已有数据与响应验证排版，不为界面调整重跑完整付费评测。
- 每个agent只交付一个有界任务，不递归派生；同类失败两次转诊断，检查点记录未完成项，避免压缩上下文后重复运行。
- 用户已要求实施，并在验收后要求重写根README、提交和推送当前分支；替换现有部署仍不在本次交付内。保留既有文档修订，范围外文件保持原样。
