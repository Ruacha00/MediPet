## 冻结输入与执行

1. 原有 66 条意图、15 组两轮对话、12 组边界，完整运行一次。
2. 新增 12 组两轮业务表达：创建、取消、复合各 4 组，与各自旧用例合计每项 5 组。新输入为专项工作负载，依据业务模板设计，不宣称独立盲测或线上分布。
3. 模型测试通过已部署 API 的评测入口调用真实 deepseek-flash，使用现有逐场景隔离 Redis / Chroma 工厂。确认动作由夹具显式执行，不称模型自主确认。应用聊天 HTTP、浏览器交互不属于此批指标。
4. 事务专项在 Docker API 容器中直接调用当前服务，使用真实 Redis 随机前缀，每组结束只删除自身前缀。没有模型参与，不计入模型完成率。
5. 每轮只执行一次，失败保留，不通过重复运行择优。保存冻结输入、源码指纹、模型参数白名单、原始结果、失败与汇总；核对部署源码、前后基线指纹及源码未变。候选不自动接受。
6. 摘要按具体场景分母计算，任何调用异常/缺失结果均不计通过；质量评分与状态断言分别报告。时延仅作观测，没有对照不写“降低”。

执行口径补记：事务脚本在每组并发创建、并发取消之后，各进行一次明确的顺序重放，以核对最终原回执，共 100 次。这些重放独立计数，不覆盖前面的 1,300 次并发请求及其冲突结果。事务脚本先固定再执行，原始文件指纹保存在事务 `configuration.json`。
