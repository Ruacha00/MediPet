## 指标怎么算

### 意图路由链路

- `intent`：取三路融合后的一个主要分类结果；当前枚举含业务类别和通用兜底，不把“66条样本”误写成66类意图。
- `intent_group`：将具体类别归入query、guidance、appointment、escalation等粗组。三个医疗类别的group仍为query，编排根据具体intent选Triage/Medication；复合需求另选辅助角色。
- `source_scores`：LLM、当前向量后端、Pattern的输入分数，用来解释判定，不是各分支准确率或校准概率；实际是semantic还是hash另看 `embedding_info`。
- `4 级紧急度`：LOW / MEDIUM / HIGH / CRITICAL是规则输出；若单独衡量它，需要独立标签集，当前66条意图结果不是紧急度准确率。
- `结构化实体`：可以按字段exact match或field-level precision/recall/F1测量；这是测量方案，不是当前已经得到的指标。

### 常用公式

- `Accuracy = 正确预测数 / 总样本数`
- `Precision = TP / (TP + FP)`
- `Recall = TP / (TP + FN)`
- `F1 = 2PR / (P + R)`
- `Macro-F1 = 各类别 F1 的平均值`
- `故障接受准确率 = 接受且正确数 / 接受数`；全拒绝时没有可计算的接受准确率，不能记成100%。
- `故障覆盖率 = 接受数 / 可判定子集总数`；必须和接受准确率一起看。

### LLM-as-Judge 能做什么

- 可以：辅助标注模糊样本、判断回复质量、校验实体归一化、给路由解释打分、生成回归分析建议。
- 不适合单独承担：最终的 Accuracy、Precision、Recall、F1 统计。
- 原因：这些分类指标需要稳定的 gold label 和可复现的预测输出，最终应由评测脚本基于标注集计算；LLM-as-Judge 更适合做标注辅助和主观质量评分。



## 逐条说明


1. `三路识别 + 4级紧急度 + 6角色`：三路提供主要意图，编排选择主辅角色；不是三个大模型投票或每次六角色并行。
2. `66条意图评测`：文件中有固定输入与gold label，不是约500条人工标注或线上用户样本；不能自行补造标注过程。
3. `Accuracy / Macro-F1 / 单类指标`：预测与标签由程序比较；固定66条单次全对不代表任意输入都正确。下方U001旧报告不证明U002语义效果；新分支须区分原始排名、同份LLM融合回放及故障接受准确率/覆盖率。
4. `6类角色`：General、Guidance、Appointment、Escalation、Triage、Medication；默认每类1实例，不是已部署集群。
5. `24份默认知识`：17份医院资料与7份医疗资料；文档数量不代表医学覆盖率。
6. `约500字符切片 + 最多3个改写查询`：按句号/换行组织切片，长句不一定严格500；原问题也保留，随后并行召回、去重、重排。
7. `RAG回答准确率`：需要问答标准与人工/规则核验；当前没有可沿用的65%→83%或88.7%结果。
8. `检索召回率变化`：需要相关文档gold set与同条件对照；目前不填91.2%或提升若干百分点。
9. `Redis 24h TTL + 15条压缩 + 最近5条`：约束工作窗口，过期不是全部历史删除；完整事项历史另存。
10. `6组Skills热加载`：文件修改后主动reload才影响后续普通角色prompt，不是自动监听或运行时授权新工具。
11. `5000字符注入预算`：控制总体Skill文本，单份正文默认3200；字符预算不是token预算，附加标题/截断标记也需区分。
12. `15组多轮 + 12组边界`：既包含模型对话，也包含明确界面动作和事务条件；不能全部等同单次自然语言问答。
13. `四维Judge`：相关性、准确性、完整性、有用性；评分失败单列，不用假零分污染有效均值。
14. `0.75阈值`：四维平均的质量通过线；模型质量高分不能覆盖业务状态失败。
15. `5%回归检测`：与人工已接受基线比较相对下降，先核对模型/数据/版本，不是每轮自动接受或自动修复。
16. `300s缓存 + 30s超时 + 熔断`：用于实际经过管理器的静态知识工具；连续5次失败/60秒恢复，不套到动态患者预约。
17. `/monitor 和 /metrics`：运行观测出口；请求成功率不等于回答正确率、临床准确率或生产SLA。
18. `精简投递版`：挑选本人讲得清的职责和两三项机制，详细指标与证据留作品集。
19. `HR开场白`：先说服务对象、业务闭环和本人贡献；如需数字，只用与职责直接相关且已核对的一项。

## 面试追问版

1. 细粒度识别与路由：项目使用LLM、本地中文语义模板向量与Pattern融合，字符hash为明确后备，输出主要意图与实体；领域打分和协作规则再选主辅角色。我会用“查号+材料”说明两步差别，而不称任意任务自动生成DAG。
2. 意图数据：gold label是固定用例期望类别，预测由识别器产生，Accuracy和F1由脚本计算。历史66条回归继续保留；U002另按表达家族分开开发/留出，标注与低字面重合规则先冻结且独立复核，再推理。开发集仅选门槛，留出不能反向改模板或阈值；共享真实LLM原响应用于三模式回放，假LLM只证明机制。数字核对正式候选，个人标注/实现职责按实际填写。
3. 按需RAG：路由后角色选择是否检索；改写、并行召回、片段去重与重排保留，动态预约直接查询。共享管理器在进程内，不声称远程MCP服务或已实测召回收益。
4. 分层记忆：工作窗口控制TTL和长度，Chroma保存摘要及资料，完整历史在Redis另存；身份作用域是参与者/患者/事项。异步Redis与线程池用于避免同步调用阻塞，关键状态仍回查服务。
5. 动态Skills：规则文件按角色/关键词注入并主动reload，角色权限仍由程序控制。分诊、药品和报告的有界信息不是诊断，也不能靠prompt自动获得更多权限。
6. Monitor与Judge：前者观察运行并影响同类实例分数；后者评价回答，业务断言检查真实状态。一个答案可能Judge通过但没有完成工具查询，路线失败与定点复测就是现有例子。
7. 说明gold label：就是“期望标签”。例如输入“明天儿科还有号吗”，期望为slot_query；实际预测是否相同由程序核对。它不是Judge分数，也不是临床标准答案。
8. 样例与药品边界：分类模板和编码参考句不会更新BGE权重，也不是药品白名单。换药名仍按查询目的匹配意图；药品工具只允许来自用户原话的药名/剂型，未知药物不能替换成样例中的已知药品。分类正确也不等于资料已收录。

职责表达：我实际负责[模块]，针对[可复现问题]完成[修改]，用[已有证据]验证[范围]；其他机制属于沿用或阅读，不据此声称全部原创。
