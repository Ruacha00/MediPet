# MediPet 文档中心

MediPet 当前不仅支持就诊对话、按需调用的 RAG 知识库、多 Agent 编排和端到端评测，也已经支持动态 Skills 加载、细粒度意图识别、意图组归一化、结构化实体提取、异步记忆/知识库访问，以及带主 Agent、辅助 Agent、路由原因和领域分数的结构化多 Agent 路由。Skills 入口为 `GET /skills` 和 `POST /skills/reload`，可把医院信息、预约、就诊准备、分诊和药品资料等处理规范按 Agent 类型注入 system prompt；Escalation 的固定响应直接由代码生成。评测入口为 `POST /eval/run`，覆盖意图识别准确率、Agent 回复质量、LLM-as-Judge 多维评分、业务断言、回归检测和优化建议生成。阅读任意文档时，都应把“可配置、可评测、可回归、可持续优化”视为本项目的重要工程能力。

这套文档保留“先理解定位和设计动机，再看模块、源码、操作与面试表达”的讲解顺序。当前医院、医生和号源均为虚构演示数据；预约使用实际持久化的演示状态，健康功能提供有限信息参考，不诊断、不开处方。医院与健康业务沿用 `bb0600c` 基线，意图语义向量部分增量更新至 `e81f447`（U002候选版本）。

U002保留三路融合，引入本地中文BGE语义编码器，并将字符哈希明确作为后备或对照。模型接通与质量验收是两件事：低字面重合样本上的向量单路准确率提高，但本次完整融合结果持平，LLM故障时的接受准确率尚未达到预声明门槛。学习和简历表述请同时保留这些范围条件。

## 建议阅读顺序

1. 初次接触：先看学习文档的定位、架构与业务流程，再对照架构图理解组件关系。
2. 动手体验：按完整使用指南运行患者预约、报告和知识操作，观察实际状态及失败结果。
3. 阅读源码：按重点代码的次序跟踪请求，结合业务流程中的记忆、Skills 和异常处理说明。
4. 准备面试：从技术亮点中挑选能讲清楚的模块，使用简历模板整理本人实际贡献，再查指标模板核对数字。

需要按模块查阅时，可继续阅读 [docs 架构说明](../docs/architecture.md)、[预约设计](../docs/appointments.md)、[健康咨询](../docs/health-consultation.md)和[评测说明](../docs/evaluation.md)。医院健康业务历史验证见 [U001 验收](../docs/internal/updates/U001-health-consultation/evidence/acceptance.md)，语义向量候选的分组结果、失败项与测试条件见 [U002 冻结对照](../docs/internal/updates/U002-semantic-intent/evidence/calibration/implementation.md)。U002真实业务链路验收仍待执行，文档示例与教学推演不充当实测结果。
