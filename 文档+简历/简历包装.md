# MediPet 简历包装指南

本文档用于把 MediPet 项目包装成简历、面试和项目展示中可讲清楚的经历。建议按真实实现描述；未测量的效果不填写数字，“在内置评测集上”也必须有真实报告。下面保留可用成稿，但“设计/实现/我”仅适用于本人实际承担的工作，不能把沿用模块全部说成独立原创。

包装重点：MediPet 当前不建议只包装成“智能就诊助手 Agent”，更适合定位为“多 Agent 就诊助手编排 / Multi-Agent Healthcare Assistant”。项目已经支持细粒度意图识别、六角色主辅协同、按需RAG、动态Skills、异步记忆访问、同类实例监控评分和LLM-as-Judge评测；还包含患者事项、幂等预约确认与有来源健康信息。这是区分“普通聊天 Demo”和“可观测、可评测、可持续迭代 Agent 工程项目”的关键点。

## 项目一句话描述

> MediPet 是面向医院、诊所及健康服务平台就诊服务场景的多 Agent 编排系统，支持就诊咨询、科室分流、号源查询、预约办理、用药信息查询与报告预处理，结合领域知识库、分层记忆、动态 Skills 和运行监控，实现可解释、可观测、可评测的服务链路。

项目介绍描述应用场景与技术能力；数据来源、接入范围和个人贡献在运行说明或面试追问中展开。当前使用预置医院演示数据，未接入真实医院系统；初步分诊、已收录药品标签和报告整理的具体边界见[健康咨询说明](../docs/health-consultation.md)，不将场景定位写成生产落地经历。

### Python 后端 / AI 应用版本

本项目当前只有Python后端，此位置改为**Python后端 / AI应用方向版本**，不沿用没有当前实现的Java、Spring AI、LangChain4j或JSON长期存储经历。保持同一项目的不同求职侧重点，不为职位虚构技术栈。

适合投Python后端、AI应用工程方向时使用。后端岗位重点讲身份、事务和恢复；AI应用岗位重点讲路由、工具边界、资料来源和评测。

```text
MediPet Python 多 Agent 就诊助手
技术栈：Python / FastAPI / Redis AsyncIO / Chroma / Vue / Tesseract / Docker Compose

- 基于FastAPI提供聊天、患者事项、预约确认、报告上传及管理接口，
  使用Vue业务卡片和Nginx同源代理完成部署与页面交互。
- 沿用并适配三路意图、主辅角色和工具循环，绑定患者事项身份，
  用真实服务结果生成卡片；共享Agent实例只保留本轮局部结果。
- 实现待确认方案与幂等执行边界，处理方案过期、改选、重复确认、
  库存竞争及确认后历史暂不可写等状态，并返回明确业务错误。
- 接入本地PDF文字提取与Tesseract中英文OCR，支持扫描/混合页和图片；

- 使用固定业务断言、真实组件和浏览器验证关键路径，
  用LLM Judge另评回答质量，保存候选和定向失败修复证据。
```

### 端到端 Agent 怎么评测？

**回答思路**

评测保留两类模型检查，并补充业务状态断言：

1. 意图识别评测：用标注用例计算 Accuracy 和 Macro-F1。
2. 端到端回复评测：真实调用 `Orchestrator.run()` 生成回复，再用 LLM-as-Judge 从四个维度打分。

四个维度是：

- `relevance`：是否回答用户问题。
- `accuracy`：信息是否准确。
- `completeness`：是否完整解决需求。
- `helpfulness`：用户能否据此行动。

业务断言独立检查真实工具、卡片、库存和患者范围；Judge不能证明预约已执行。Judge失败不进入有效均值。评测器与人工已接受基线比较，相对下降超过5%才标记regression，并生成建议；不是自动与上一轮候选比较。

U001 历史完整模型候选66/66意图，30/30质量、26/27业务，共57/58；路线提示修复后原样两轮3/3，未重跑完整58项。报告仍为`candidate`。后端684 passed/21 skipped与前端35项是另一层验证，最后提示修复后有119项定向检查。无需把全部数字堆进简历，细节见[验收](../docs/internal/updates/U001-health-consultation/evidence/acceptance.md)。

U002 可以讲清本地语义编码、整路降级、同空间缓存和受控对照的实现。若被追问效果，应说明低重合向量单路改善、三模式融合持平，LLM 故障接受准确率未达预定门槛；不能写成整体助手准确率提升或全部验收完成。可直接使用的数字与口头表述集中在[指标模板](带数据指标的加强版简历模板.md)。

#### 口头表达：30秒与一个深入案例

“项目围绕患者事项做就诊协作：先查号和材料，选择后只生成方案，按钮确认才执行Redis事务。我重点讲[自己负责模块]，因为这里要把模型文字、实际业务状态和可恢复历史分开。健康扩展只提供有限分诊、指定标签和本地报告整理。”

深入追问可选一个本人实际参与的例子：

- 路线续问：首轮有普通路线，第二轮要无障碍时只复述而未调用工具；业务断言失败，修复Guidance提示后原输入两轮3/3，完整报告不覆盖。
- 混合PDF：页眉有文字不代表正文已提取；对含图页补OCR，保留文字层并标注待核对，使用合成文件回归。
- 确认重试：业务成功、历史失败时保留原回执，重试补历史和窗口失效，不再次扣库存。

这些是项目记录，不自动成为个人经历。证据见[审查](../docs/internal/updates/U001-health-consultation/evidence/review.md)与[路线复测](../evaluation/reports/live-20260916-u001-route-fix/notes.md)。
