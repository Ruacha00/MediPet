`tests/browser/run_evaluation.py` 默认只检查本地输入。协调冻结业务代码、Skills 和评测数据后，显式使用 `--execute` 才从真实页面点击一次“运行评测”。默认入口为 `http://127.0.0.1:5173`，经同源代理访问已配置的 API 8010，最长等待 1800 秒，不替换请求数据、不自动重试。

容器入口另用 `--url http://127.0.0.1:18088 --expected-api http://127.0.0.1:18000` 明确记录代理目标，并指定新的输出目录。脚本只能核对宿主工作树基线文件；容器 `api-data` 内的接受基线须由协调者补充运行前后证据，不能将宿主文件检查当作容器保护证明。

每次运行使用新目录，保存：

- `response.json`：真实 `/eval/run` 返回原文，完整保留成功、失败与跳过。
- `summary.json`：意图误判、有效质量分、业务失败、调用/Judge 失败与跳过摘要。
- `execution.json`：时间、耗时、请求次数、页面错误、源码变化和基线文件前后指纹。
- `inputs.json`、`source-manifest-before.json`、`source-manifest-after.json`：输入内容及运行源文件 SHA-256。
- `model-parameters.json`：不含密钥的本地配置白名单、源码参数表达式和角色默认值；实际模型/Judge 参数同时从返回报告核对。
- 页面运行前、完整报告、失败筛选截图，以及渲染后的 HTML 和文字；异常时保留失败截图及错误记录。

报告保持 `candidate`，脚本不调用 `accept_baseline`。完成后先查看完整失败列表与业务状态，由用户决定是否接受；测试通过数、结果项通过率与模型准确率各自解释。
