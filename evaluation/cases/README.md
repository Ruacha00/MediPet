# MediPet 评测输入

- `intents.json`：66 条独立措辞。原 54 条完整保留；U001 新增 symptom_query、medication_query、report_query 各 4 条。标签使用当前 IntentCategory，expected_agent 使用当前六角色值（报告由 triage 处理）。
- `dialogs.json`：15 组两轮场景，固定参与者、患者及前置状态，记录可核对的业务断言。原 12 组保留；新增成人症状（明确年龄）、布洛芬200mg普通片与华法林标签核对、粘贴多行合成报告与缺失范围。
- `boundaries.json`：12 组边界，包括未确认、重复操作、旧方案、身份冲突、无结果、检索故障、否定与一般急症咨询、模型不可用、到期和并发。

数据集固定业务时钟为 2026-09-16 10:00 Asia/Shanghai；使用明和虚构医院的预置患者、科室、医生与七天号源。正式运行应记录实际采用的时钟、模型、参数、数据摘要和代码版本。不是每条意图输入都能独立执行业务，单轮分类评测与多轮事务场景分开。

`turns` 是用户聊天内容。`setup` 是用例前置资料，`between_turns` 的数字键为下一轮的零基索引，`after_turns` 是聊天后的明确界面动作。患者切换、归档/恢复和确认属于测试驱动的用户操作，不能把这些动作伪装成模型工具权限。未填写操作的用例不得擅自执行确认。

`assertions` 是预期业务事实说明，由对应确定性测试和场景驱动核对，不能用 Judge 的语言评分替代。号源和预约编号必须从当次结果取得，文档不硬编码可执行 ID。检索故障、模型故障和竞争边界需显式故障注入，不以正常问答代替。

完整输入现在对应 66 条意图、27 个业务场景（15 对话 + 12 边界）和 30 次对话 Judge。边界不调用 Judge；这些数量是输入规模，不是通过率。新增医疗业务断言只使用既有 `agents.include` / `has_artifact`，能证明角色与结构化卡片出现，不能证明具体医学内容正确；具体科室、标签警示和数值比较另由服务/接口测试核对。

新增措辞未逐字复制 `_TEMPLATES`，也未根据真实模型评分调整；病例与报告数字均为合成评测输入，不是医疗建议。先验证加载、实际工具结果的断言与反例，再统一执行真实模型评测。原 54/12/12 报告只代表对应旧输入和代码；不能推算本次 66/15/12 的质量结果，候选报告与人工接受基线继续分开。
